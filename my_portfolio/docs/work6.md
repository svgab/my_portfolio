## Работа 6: Паттерн проектирования State (Состояние) в Python

**State** — это поведенческий паттерн проектирования, который позволяет объекту изменять своё поведение в зависимости от внутреннего состояния. При смене состояния объект как будто меняет свой класс.

Главная идея паттерна:
вместо большого количества `if/elif`, проверяющих состояние объекта, логика поведения переносится в отдельные классы состояний.

Объект-контекст делегирует выполнение операций текущему объекту состояния.

---

В классической реализации участвуют три основных элемента:

**1. Context (контекст)**
Основной объект, чьё поведение зависит от состояния.

**2. State (абстрактное состояние)**
Интерфейс, который описывает действия, возможные для каждого состояния.

**3. ConcreteState (конкретные состояния)**
Классы, реализующие поведение для каждого состояния.

---

# Пример: лифт с двумя этажами

Рассмотрим реализацию паттерна на примере простого лифта.
Лифт может находиться на **первом** или **втором** этаже и реагирует на кнопки **вверх** и **вниз**.

Код реализации: 

---

# 1. Контекст — класс Elevator

Контекст хранит текущее состояние и делегирует ему обработку действий.

```python
class Elevator:
    _state = None
```

В конструкторе задаётся начальное состояние лифта.

```python
def __init__(self, state: State) -> None:
    self.set_elevator(state)
```

Метод смены состояния:

```python
def set_elevator(self, state: State):
    self._state = state
    self._state.elevator = self
```

Здесь происходит две вещи:

1. Сохраняется новое состояние
2. Состоянию передаётся ссылка на сам лифт

Это важно, потому что состояние может **само менять состояние лифта**.

---

Методы кнопок просто **делегируют выполнение состоянию**:

```python
def push_down_btn(self):
    self._state.push_down_btn()

def push_up_btn(self):
    self._state.push_up_btn()
```

Контекст не знает, что конкретно происходит — это решает текущее состояние.

---

# 2. Абстрактный класс состояния

Абстрактный класс определяет интерфейс всех состояний.

```python
class State(ABC):
```

Он хранит ссылку на лифт:

```python
self._elevator = None
```

И предоставляет property:

```python
@property
def elevator(self) -> Elevator:
    return self._elevator
```

Это позволяет состоянию менять состояние лифта:

```python
self.elevator.set_elevator(...)
```

Абстрактные методы:

```python
@abstractmethod
def push_down_btn(self) -> None:
    pass

@abstractmethod
def push_up_btn(self) -> None:
    pass
```

Каждое состояние должно реализовать эти методы.

---

# 3. Конкретные состояния

## Первый этаж

```python
class FirstFloor(State):
```

Если нажать кнопку вниз:

```python
print("Уже на первом этаже")
```

Лифт уже внизу, ничего не происходит.

Если нажать вверх:

```python
print("Лифт поднимается на второй этаж")
self.elevator.set_elevator(SecondFloor())
```

Здесь происходит **смена состояния**.

---

## Второй этаж

```python
class SecondFloor(State):
```

Кнопка вниз:

```python
print("Лифт опускается на первый этаж")
self.elevator.set_elevator(FirstFloor())
```

Кнопка вверх:

```python
print("Лифт уже на втором этаже")
```

---

# Работа программы

```python
myElevator = Elevator(FirstFloor())
```

Начальное состояние — **первый этаж**.

---

### Проверка состояния

```python
myElevator.present_state()
```

Вывод:

```
Лифт на FirstFloor
```

---

### Нажатие кнопки вверх

```python
myElevator.push_up_btn()
```

Вывод:

```
Лифт поднимается на второй этаж
```

Состояние меняется на `SecondFloor`.

---

### Проверка состояния

```
Лифт на SecondFloor
```

---

### Нажатие вниз

```
Лифт опускается на первый этаж
```

Состояние снова меняется.

---

# Что важно в этом паттерне

### 1. Контекст не знает деталей поведения

`Elevator` не содержит логики:

```
если этаж == 1
если этаж == 2
```

Всё поведение вынесено в состояния.

---

### 2. Состояния могут менять друг друга

Каждое состояние может вызвать:

```
self.elevator.set_elevator(...)
```

Таким образом происходит переход.

---

### 3. Код легче расширять

Если добавить третий этаж, достаточно создать новый класс:

```
ThirdFloor(State)
```

И описать переходы.

Контекст менять почти не потребуется.

---

# Когда использовать State

Паттерн полезен, когда:

* поведение объекта зависит от состояния
* код содержит большое количество `if/elif`
* состояние влияет на доступные операции
* состояние должно менять поведение объекта во время работы

Типичные примеры:

* лифты
* автоматы (vending machines)
* игровые персонажи
* сетевые соединения
* жизненные циклы объектов
* workflow-системы

---

# Плюсы паттерна

**1. Убирает сложные условные конструкции**

Вместо:

```
if state == A
if state == B
```

логика распределяется по классам.

**2. Улучшает расширяемость**

Добавление нового состояния не ломает существующий код.

**3. Логика состояния локализована**

Каждое состояние содержит только свою логику.

---

# Минусы

**1. Увеличивается количество классов**

Для каждого состояния нужен отдельный класс.

**2. Может усложнить архитектуру**

Если состояний мало, паттерн может быть избыточным.

---

# Короткое резюме

State — это способ организовать код, при котором:

* объект хранит текущее состояние
* поведение определяется объектом состояния
* состояния могут переключать друг друга
* контекст делегирует операции состоянию

В результате код становится чище, расширяемее и лучше соответствует принципу **Single Responsibility**.
